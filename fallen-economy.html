Server product case study

Fallen Economy

A deployable Paper 1.21.11 economy package combining internal money, configurable shops, selling, payments, auctions, escrow-backed buy orders, timed tools, Sell Wands, and a separate optional Essence currency.

Package repository Installation Operator docs

01 / Problem

A server economy becomes fragile when every workflow belongs to a different plugin.

Balances, shops, selling, auctions, orders, premium currency, and utility tools all affect the same player economy. Splitting them across unrelated systems makes pricing, permissions, data ownership, and operator support harder to reason about.

Fallen Economy packages the normal money loop into one plugin while keeping optional integration points for servers that already use Vault or PlayerPoints.

02 / Constraints

Useful on its own, compatible where compatibility matters.

Standalone money

The normal dollar balance is stored and managed internally without another economy provider.

Optional Vault

Vault exposes the internal balance to compatible plugins but is not required to start.

Separate Essence

PlayerPoints backs the optional Essence shop without mixing premium and normal balances.

Operator-owned config

Shops, sell values, limits, and pricing behavior remain visible in YAML files.

03 / System

The package covers the complete earn, spend, trade, and administer loop.

Balances

Internal money storage, starting balances, transfers, and administrative give, take, and set commands.

Shops

Normal and Essence categories, in-game editing, amount controls, confirmation, and configurable prices.

Selling

GUI, held-stack, and inventory selling backed by a large generated value table.

Auctions

Player listings, purchase confirmation, sorting, cancellation, and configurable listing limits.

Buy orders

Up-front escrow, partial fills, refunds, immediate seller payment, and offline item delivery.

Utility tools

Normal tools, owner-bound timed tools, and limited-use Sell Wands with explicit transfer rules.

The design keeps the everyday dollar economy self-contained while treating external currencies and compatibility APIs as optional bridges.

04 / Reliability

Economic actions are designed around explicit state changes.

Purchase confirmation

Shop clicks open an amount and confirmation screen before a player is charged.

Funded orders

Creating a buy order withdraws its full escrow so an accepted fill can always be paid.

Offline delivery

Items owed to an offline buyer are persisted and delivered automatically on the next join.

Tool ownership

Timed tools drain only while the owner is online and transfer only through explicit loss or drop.

06 / Lessons

What this project demonstrates.

  • Currency boundaries should be explicit when different systems own different balances.
  • Escrow and offline delivery turn marketplace commands into a reliable state machine.
  • Configuration quality matters when server operators are the real product users.
  • A complete package includes installation, commands, pricing rules, and recovery behavior.
